## 1.7.4 的编译器修复验证

用户提供的 1.7.3 日志来自 vivo V2507A、Android 16 / API 36，主线程抛出 `VerifyError`，明确拒绝校验 `ReaderScreenKt.ReaderScreen`。对实际安装包进行控制流与寄存器类别检查：1.7.1 为零错误，1.7.2 和 1.7.3 各有三处相同错误。在翻页布局分支，物理寄存器 v330（p10）仍保存对象引用，却被当作 Float 传给 `Float.valueOf(F)`，随后通过数值 move 用作 `fillMaxSize` 的浮点参数；首次错误调用位于 DEX 偏移 0x38D7。校验会检查整个方法，因此滚动、翻页及漫画都会在阅读页加载时失败。

当前 AGP 8.9.2 内嵌 D8 8.9.35，早于官方 [b/408438353 修复](https://r8.googlesource.com/r8/+/8e12a687d4bcabbc5acbc5c954812d919aaf3f00)。该缺陷涉及超过 256 个寄存器的方法中，参数寄存器位置计算与常量重新生成时的错误分配。按 [R8 官方覆盖方式](https://r8.googlesource.com/r8/+/refs/heads/main/README.md#replacing-r8-in-android-gradle-plugin)，在 settings.gradle.kts 的 pluginManagement/buildscript 单独固定 `com.android.tools:r8:8.11.18`，保留原 AGP、Gradle、Kotlin 和 Compose 版本。

使用同一份 ReaderScreenKt.class（SHA-256 B683F1FB11991EB588E8AF0BD7078ED79C965C3D84426CF8BD47689A4953465C）及相同 classpath、Android 35 库、debug/intermediate/min-api 26 参数分别执行两个 D8：旧 8.9.35 输出 337 寄存器、三处错误；新 8.11.18 输出 344 寄存器、零错误。最终组装 APK 的 ExtractMarker 确认实际 D8 版本为 8.11.18，同一检查器也报告零错误。该对照直接验证更换编译器消除了已确认的字节码错误，无需修改阅读页源代码。

可复现脚本、同一输入快照、旧新输出及 JSON 结果保存在 `.tools/reader-verifier-audit`。`reader-dex-categories.mjs` 检查正常控制流中的寄存器类别，`standalone-compare.ps1` 执行两个编译器的对照；检查器不模拟完整 ART 的精确引用子类型、未初始化对象及异常处理边，因此不替代 Android 真机运行。本轮仍未在 vivo 上执行修复 APK。

单条异常信息上限由 1,000 扩大到 16,384 字符，总报告继续限制为 32,768 字符，以保留长方法签名后的寄存器说明。新增回归使用重复长签名后附具体校验错误，检查该说明仍完整保存；另补充阅读页的章节切换、进度拖动/返回按钮、半屏设置、语音悬浮栏操作回归。

新增 5 项回归与原有 310 项全部通过。语速使用真实拖动并松手，按滑块最终语义值核对控制器收到的速度；同步颜色检查实际文字布局中的颜色。桌面窗口截图 API 不支持此 Robolectric 环境，像素截图仍属于设备验证范围。启动回归显式初始化模拟 WorkManager，并在轮询时处理 Android 暂停主循环中的 IO 回调，结束时先取消 ViewModel 并等其任务完成；章节导航先等待按钮可用。这些调整仅用于确定性测试，不更改应用运行逻辑。

朗读依据 Android API 26 的 [onRangeStart 回调](https://developer.android.com/reference/android/speech/tts/UtteranceProgressListener#onRangeStart(java.lang.String,%20int,%20int,%20int)) 跟踪正在发声的原文位置；引擎不提供范围回调时，按不超过 240 个字符的句段推进。翻页模式另按实际文本页拆分朗读段，跳过插图页，当前段不越过页末，因此大字号下没有范围回调也能逐页跟随。播放代次及完整 utterance ID 拒绝停止、重启和同次播放的旧句段回调。滚动模式仅在正在朗读的行离开可见范围时滚动。

手动拖动开始时暂停语音和自动跟随，松手并等待惯性滚动结束、位置稳定后，从新的可见原文锚点继续；音量翻页、目录和进度调整采用同样的暂停与恢复行为。播放中修改字号或间距时先暂停，排版与位置恢复完成后从原锚点按新页边界续读。未开启播放时，手动导航不会启动朗读。

新增 3 项 TTS Robolectric 回归已通过，覆盖范围回调的原文偏移、跨句段和跨章、旧回调与旧错误的拒绝、停止/重启及没有范围回调的推进；朗读文本不包含显示间隔字符，emoji 不被拆开。新增 4 项 Android 界面回归仅已编译，覆盖滚动跨章与手动拖动停稳后续读、翻页/音量/目录导航、自然结束的最终锚点，以及大字号无范围回调时的页末/插图/字号重排边界。未验证设备 TTS 的实际声音或手机上的跟随效果。

## 1.6.2 的新增验证

段距由 0.4em 加倍至 0.8em，20sp 字号 / 40px 行高下，额外段距从 8 增至 16，换段基线从 48 增至 56；已有空行、普通段内行高和人工文字块边界不改变。现有 8 项段距 JVM、4 项实际 NativeGraphics 测量和原生行高用例已更新期望。分页缓存算法升至 8，正文解析版本、选区与原 UTF-16 位置不变。

“云端版本校验无效”来自旧 ETag 校验，不是正文发生变化的说明。已登记书籍的记录更新通过普通 GET 确认索引存在该书后直接返回，不再获取 ETag 或改写公共索引；正文资产相同时沿用旧归档，只更新阅读记录。新增书籍在整理与大上传前预检索引，兼容安全的无引号 opaque ETag 并原样用于 If-Match，保留标准引号版本及 HTTP 412 冲突重读。弱 ETag 不去掉 W/ 冒充强版本，不能安全写新索引时提前说明。兼容依据是产品作者的第一手资料：[流畅阅读 WebDAV 说明](https://read.thinkstu.com/guide/webdav)、[Agentero 实测记录](https://docs.agentero.app/backend/sync/)；尚未读取用户账号的实际响应。

新归档按 4 MiB 分块，兼容旧 128 MiB 清单，最多 8192 块 / 32 GiB；文件和元数据原有限制继续生效。每书、每账号的私有暂存保存原 ZIP、revision、内容/资产摘要与服务端已确认块，AtomicFile 在成功响应后提交断点。中断和取消保留暂存，重新运行检查内容与归档摘要后跳过已确认块；未确认的当前块会重传，源变化使旧暂存失效。正文与封面全部成功后才提交 manifest，索引提交成功后清理本地暂存；索引提交失败后的下一次操作可复用已提交书体。删除本地书籍会取消该书任务并清理私有暂存。旧版未保存断点的半成品不具备这一恢复能力。

连接错误及 HTTP 429/500/502/503/504 每请求最多尝试三次，有限等待后交给任务退避；认证、权限和空间等永久 HTTP 失败不按网络中断重试。本地源文件被删除或授权撤销也直接报告。手动上传转为持久 WorkManager 请求，CONNECTED 网络约束、expedited 配额不足时回退普通任务、dataSync 前台服务与最多五次退避重试；进度每 500ms 节流并最终等待保存，重开应用从 WorkInfo 恢复，成功历史只合并上传资格和时间而不回写旧阅读位置。自动备份仍受非计费网络限制。系统允许通知时可使用通知中的取消操作；强制停止或厂商清理仍可能中断，不能承诺切后台永不掉线。实现依据 [Android 长任务说明](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running) 与 [dataSync 要求](https://developer.android.com/develop/background-work/services/fgs/service-types#data-sync)。

10 MB 没有触及坚果云官方 500 M WebDAV 单文件限制，但备份包含原文件、解析正文、插图与字体，实际归档可能比原文件大；初次备份还需计算摘要与压缩。没有测量用户账号的上传带宽，也没有把慢直接归因于限流。服务端限制见 [坚果云官方说明](https://help.jianguoyun.com/?p=2064)。本轮测试为本地模拟 HTTP、磁盘归档和任务配置；真实账号、手机切后台与通知仍需运行验证。

## 1.6.3 的新增验证

上传圆环中心显示一个可点击的 ×，阅读首页、历史以及书架网格/列表共用；仅当前上传或等待重试时可取消，下载/删除进度不显示该按钮。保存与入队使用同一队列互斥锁，已开始的 WorkManager 数据库入队等待完成后再取消书籍 tag，取消接口等待持久取消状态。账号＋书籍的自动暂停状态防止立即补传，已确认块及旧备份保留，手动上传成功后恢复。上传 guard 与 200ms watcher 可取消独立客户端的阻塞请求；取消引起的 IOException 优先转为取消，而不退避重试。共享回归同时验证取消 Job 和在 Job 仍活跃时暂停自动备份的阻塞场景；实际 WorkManager 队列回归查询到了 ENQUEUED → CANCELLED。

已启用云上传的书籍菜单增加“删除云端文件”确认。先暂停本书自动备份并等待手动上传取消，再持 cloudOperationMutex 删除仅 `books/<safeId>/` 的整个目录，包含旧 revision 与残缺块；预检索引版本，条件写遇到 412 重读并保留其他书。404 视为已经删除，207 部分失败不报告成功，目录删除后索引失败允许重试。成功清理该书 pending、云封面缓存和历史资格；本地正文、阅读位置和笔记保留，只有未下载的云端占位书与关联记录移出书架。删除与取消都协调自动 worker 的 guard 与同一把锁，旧 history 不会在重启后重新开启资格。协议依据 [WebDAV DELETE for Collections](https://www.rfc-editor.org/rfc/rfc4918#section-9.6.1)。

新上传块为 1 MiB（1,048,576 字节），32 GiB 最多 32768 块，原元数据与资产数量限制不变。checkpoint v2 保存 partBytes；旧 v1 按原 4 MiB 读取并继续同 revision，避免已确认块被新 1 MiB 边界误解释。旧 128 MiB 已提交清单仍能读取。4 项新增界面回归覆盖网格/列表真实触摸取消不打开正文、首页/历史入口、删除菜单条件及确认/取消、繁忙禁用；仅已编译。没有连接真实坚果云账号执行删除，也未在手机上验证按钮触摸或取消时的系统通知。
