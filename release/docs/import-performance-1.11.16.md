# 1.11.16：完整导入缓存与阅读优先

本轮保留“导入完成后全书缓存可用”的约定，继续保存完整 EPUB／MOBI 原件。没有改为边读边初始化全书，也没有增加开书时的全文扫描或全书页数统计。已有章节窗口、相邻章节预加载与原书 WebView 展示保持原路径。

## 本次改动

1. **复用扫描结果。** EPUB 的目录锚点、注释识别与普通章节文字提取共用当前文档的标签扫描；分节展示复用原始标签表。无链接的文档跳过注释可见文本副本，无图片的普通章节不再为插图标记重建 HTML。包含注释／特殊样式的转换仍使用原有处理，确保文字和 UTF-16 定位一致。
2. **限制在途章节。** EPUB 按 spine 资源读取，处理完的章节立即写入缓存，解析结果只保留轻量目录。源文档缓存最多两份，提交但未回收结果的章节任务最多四个，消费不及时就等待，避免任务队列保留全书 HTML。同一资源内的多个目录锚点仍检查真实分界，保留结构、父级目录与跨文件注释。
3. **降低缓存写入开销。** 展示清单以缓冲 JSON Writer 写出，避免先构造包含整章 HTML 的 JSON 字符串及其完整 UTF-8 副本；空注释字典省略。MOBI 共用样式文件及哈希查询结果。新书私有暂存阶段不用逐章 fsync，已有缓存更新仍走 AtomicFile。缓存版本 3 与旧字段读取保持兼容，没有引入新的云端格式。
4. **让阅读优先。** EPUB 缓存线程降低优先级；进入阅读页后，在途任务上限缩为一个。触摸、拖动、翻页及进度调整会持续刷新短暂让路期限，导入在取消检查点等待，交互停稳后继续。等待只发生在导入端，阅读加载不获取导入锁。原文件复制、HTML 扫描与资源复制也包含检查点；退出阅读后恢复正常导入并发。进度通知最多约每 100ms 更新一次，完成状态立即发送。
5. **分别记录耗时和阅读行为。** 每次导入记录复制、目录、资源读取、标签扫描／注释、正文转换和缓存写入的累计时间及计数；加入 `ERead.import.*` 系统 trace 区段。最近 20 份诊断保存在本机缓存 `import-diagnostics/`，仅包含阶段名、耗时、格式及数量，不含书名、路径、账号或正文。并行阶段的累计耗时可能重叠，不能相加当作总耗时。

MOBI 正常内置目录链路保留一份解压 HTML 和轻量章节区间，逐章恢复片段、提取文字并写入缓存，消除另一整套已分章 HTML 的同时持有。MOBI 的压缩格式仍需首次解压；没有有效目录且需要按正则重新分章时，继续保留全书文字处理回退。单个超大 HTML 资源也仍需完整读取，不承诺所有书籍都只占固定少量内存。

## 验证与边界

生产导入与原解析结果对照正文、UTF-16 偏移、注释内容／范围、插图顺序及 CSS；另覆盖旧缓存读取、编辑写回、云端物化、取消后无残留写入，以及阅读时单任务限制。源文件使用隔离副本，未改动用户原件。9 个公开 EPUB 样本覆盖 EPUB 2／3、字体、内链、竖排、SVG 等结构；私人样本只保存在本机测试位置，不纳入安装包或仓库。

电脑端《诡秘之主》样本为 27,663,081 字节、1415 章。优化前一次测量：目录 387ms，正文／目录处理至 881ms，缓存 1828ms，共 2709ms；开发中优化后多次观测约 1.1～2.6 秒。测试执行顺序及运行时预热不同，这些数据用于定位阶段，**不作为手机提速比例或统计性能承诺**。每次优化后的导入均另外完整对照章节文字及位置；这段验证不计入 `totalMs`。

阅读侧复用真实 Compose 启动、滚动、翻页与朗读交互回归，并验证导入让路与取消。既有 Macrobenchmark 工程记录设备帧时间与系统 trace，使用说明见 [Android 性能基线](../../app/benchmark/README.md)。按用户要求未运行真机，因此尚无导入期间的手机帧率、PSS 峰值、温度或耗电对照，不声称已保证 120 帧。

书库版本 13、WebDAV 协议 1、EPUB 内容版本 10、MOBI 内容版本 8 不变，不强制重建旧书缓存、重新分章或迁移笔记。TXT／PDF 的解析与阅读链路未替换。本轮只生成本地 1.11.16 安装包，不发布 GitHub／网盘，Windows 工程和本地交接文档保持原样。
