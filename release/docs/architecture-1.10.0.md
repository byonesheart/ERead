# 1.10.0 代码职责与性能验证

本轮先修复页面切换的封面闪动，并在既有按章缓存和独立位置文件的基础上收拢数据访问与异步状态，没有迁移数据库或启用代码压缩。

| 职责 | 入口 | 约束 |
| --- | --- | --- |
| 封面 | `BookCoverCache` | 阅读首页和书架共用缓存，按位图字节限制容量；热切换首帧直接复用。文件校验、解码及云端封面虚化在后台进行，淘汰时不回收仍在绘制的位图。 |
| 保存 | `LibrarySaveCoordinator` | 集中去抖、取消、串行提交、结构与位置的判断、退出 flush 和失败处理。保存基线与成功写入一起提交，失败后仍可重试。 |
| 章节访问 | `ReaderChapterStore` / `ChapterTextAccess` | 阅读准备、搜索和朗读使用相同正文访问入口。仅保留当前及相邻准备结果，远章读取不准备样式或扩充正文缓存。 |
| 朗读会话 | `ReaderSpeechSession` | 按一本打开的书管理准备任务、取消、音频焦点和引擎更换。准备失败明确提示，旧准备结果不能启动新的会话。视口跟随及文字选区仍由阅读界面管理。 |
| 布局 | `ReaderLayoutSession` | 用未准备、准备中、恢复中、可阅读、失败五种状态集中转换，保留布局代次与恢复请求编号。准备和视口恢复均完成后才允许保存进度。 |

成功读取到空字符串才是合法空章节。小说正文引用缺失、文件无法读取或 UTF-8 损坏会产生带章节信息的错误，不再被替换为空正文。没有 OCR 引用的漫画或 PDF 页仍可正常按原图阅读；已声明的 OCR 文件损坏则明确报错。初次打开失败可以重试，搜索中遇到失败也会显示失败原因。

封面热切换不在主线程查询文件属性。同一路径被外部替换时，会先保留已显示图片，后台校验后更新；书籍封面路径或内容版本变化则立即使用新缓存键。容量淘汰可能使较早离开视口的封面再次解码，这是有界缓存的正常行为。

WebDAV 设置展示应用内部实际的 `files/books` 下载根目录，书籍位于各自子目录。还原书籍信息的进度由真实的目录读取、逐本读取、匹配和保存阶段推进；未知总量时显示不定进度。设置和书架共用同一进度状态，仅阻止重复还原，不占用书籍上传槽位。

## 整书页索引的实际状态

`ReaderBookPageIndex` 的工厂在生产阅读路径中没有调用方，当前保留了历史实现、兼容参数、清理入口和测试。本轮没有重新接入，也没有因为测试存在就把它记为已使用的性能优化。

实际阅读仍使用 `ReaderChapterStore`、`readerCachedChapterPages` 和当前章节页码；不会为打开一本书或切换模式汇总整本书的页数。

## 性能基线

独立的 [Macrobenchmark 工程](../../app/benchmark/README.md) 提供冷启动、三页热切换、打开示例小说和连续滚动四个场景。性能测试安装包使用独立包名，不访问正式安装的书库。通过正常界面确认首次协议，缺少样本或正文加载失败时测试应失败，不能把空页面当成快速完成。

没有连接真机时只编译测试包，不记录或宣称性能基线。冷启动测量首次显示时间 TTID，未调用 `reportFullyDrawn()`，因此不宣称得到完整绘制时间 TTFD。实际比较应保留相同设备、系统、刷新率、字体、书库、编译模式和温度条件，保存 JSON 与 Perfetto trace。

取得真实设备数据后，再评估 Room 是否值得替换剩余结构 JSON 保存、R8 是否改善安装体积与启动，以及 Baseline Profiles 是否改善实际交互。此轮保持现有持久化格式、签名和正式构建的 R8 开关，避免把架构修复与工具链升级混在一起。
