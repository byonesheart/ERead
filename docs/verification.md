## 1.7.4 的编译器修复验证

用户提供的 1.7.3 日志来自 vivo V2507A、Android 16 / API 36，主线程抛出 `VerifyError`，明确拒绝校验 `ReaderScreenKt.ReaderScreen`。对实际安装包进行控制流与寄存器类别检查：1.7.1 为零错误，1.7.2 和 1.7.3 各有三处相同错误。在翻页布局分支，物理寄存器 v330（p10）仍保存对象引用，却被当作 Float 传给 `Float.valueOf(F)`，随后通过数值 move 用作 `fillMaxSize` 的浮点参数；首次错误调用位于 DEX 偏移 0x38D7。校验会检查整个方法，因此滚动、翻页及漫画都会在阅读页加载时失败。

当前 AGP 8.9.2 内嵌 D8 8.9.35，早于官方 [b/408438353 修复](https://r8.googlesource.com/r8/+/8e12a687d4bcabbc5acbc5c954812d919aaf3f00)。该缺陷涉及超过 256 个寄存器的方法中，参数寄存器位置计算与常量重新生成时的错误分配。按 [R8 官方覆盖方式](https://r8.googlesource.com/r8/+/refs/heads/main/README.md#replacing-r8-in-android-gradle-plugin)，在 settings.gradle.kts 的 pluginManagement/buildscript 单独固定 `com.android.tools:r8:8.11.18`，保留原 AGP、Gradle、Kotlin 和 Compose 版本。

使用同一份 ReaderScreenKt.class（SHA-256 B683F1FB11991EB588E8AF0BD7078ED79C965C3D84426CF8BD47689A4953465C）及相同 classpath、Android 35 库、debug/intermediate/min-api 26 参数分别执行两个 D8：旧 8.9.35 输出 337 寄存器、三处错误；新 8.11.18 输出 344 寄存器、零错误。最终组装 APK 的 ExtractMarker 确认实际 D8 版本为 8.11.18，同一检查器也报告零错误。该对照直接验证更换编译器消除了已确认的字节码错误，无需修改阅读页源代码。

可复现脚本、同一输入快照、旧新输出及 JSON 结果保存在 `.tools/reader-verifier-audit`。`reader-dex-categories.mjs` 检查正常控制流中的寄存器类别，`standalone-compare.ps1` 执行两个编译器的对照；检查器不模拟完整 ART 的精确引用子类型、未初始化对象及异常处理边，因此不替代 Android 真机运行。本轮仍未在 vivo 上执行修复 APK。

单条异常信息上限由 1,000 扩大到 16,384 字符，总报告继续限制为 32,768 字符，以保留长方法签名后的寄存器说明。新增回归使用重复长签名后附具体校验错误，检查该说明仍完整保存；另补充阅读页的章节切换、进度拖动/返回按钮、半屏设置、语音悬浮栏操作回归。

新增 5 项回归与原有 310 项全部通过。语速使用真实拖动并松手，按滑块最终语义值核对控制器收到的速度；同步颜色检查实际文字布局中的颜色。桌面窗口截图 API 不支持此 Robolectric 环境，像素截图仍属于设备验证范围。启动回归显式初始化模拟 WorkManager，并在轮询时处理 Android 暂停主循环中的 IO 回调，结束时先取消 ViewModel 并等其任务完成；章节导航先等待按钮可用。这些调整仅用于确定性测试，不更改应用运行逻辑。

漫画导入仅扫描文件名、组织页面并生成第一页缩略封面，不解析 PDF 正文、作者或标题元数据；PDF 使用 PdfRenderer 获取页数，PageSource.textPath 为 null。独立漫画 PDF 的书名和章节名取文件名（去扩展名）；文件夹根散图章取根目录名，子目录和 PDF 章取对应名称。文件夹树只扫描一次并复用目录列表，按实际支持文件数量整理；原文件引用和自然排序保持。小说模式 PDF 仍保留元数据和文字层提取，用于搜索/朗读。

TXT / EPUB / MOBI 在翻页模式下导入保存书架后，于同一导入任务中预排版，显示实时“预排版”进度；滚动模式跳过全书分页。首页测量与阅读页相同的 safeDrawing 区域；共享布局函数逐边扣除阅读页固定顶部/底部与正文 padding，并使用当前字体、密度、fontScale 和布局方向。预排与阅读使用相同文本、源样式、插图位置、分页实现及缓存键；预排失败保留已导入书籍并显示说明。冷启动外部打开若测量尚未就绪，等待最多一秒，未就绪则明确提示首次阅读时排版。翻页模式改变字体、内容或屏幕尺寸仍需计算对应布局。

漫画整理对可读目录/PDF 分支执行递归单分支合并，空目录不参与分支计数。根目录压缩后的多分支作为章节；章内多分支作为小节，并保存任意层嵌套小节的章内绝对页码范围。单一包装目录不会多出一章，例如“书名/包装目录/第1话、第2话”直接形成两章；父目录散图和唯一 PDF 合在父目录中。目录可点击小节跳到首张，当前小节按半开页码范围定位，阅读状态显示所在小节路径。数据格式升至 schema 5，旧书缺失小节字段默认空列表，已有章节和标注 ID 不变。

分页使用独立 TextMeasurer 在后台分块计算，显示进度并允许退出；字号变化或离开阅读页会取消旧任务。磁盘页表按内容、字体和屏幕尺寸复用，使用 AtomicFile 提交，校验损坏或不匹配的缓存后重新计算。1.5.0 保留每本最近三套布局，每套最多 4 MiB / 200,000 页，命中刷新最近使用时间；切回常用字号可直接复用。清理应用缓存会触发重新计算，移出书架同时删除该书各套页表。字号、行距、字距滑杆松手后才提交设置，亮度仍实时变化。设置仍为阅读页内贴底、满宽、最多半屏的面板。

MOBI 的 HTML 锚点一次索引，UTF-8 filepos 按排序目标一次解码定位，避免逐目录项扫描全文及反复解码前缀。源样式规则预编译，单个样式表有限缓存，级联顺序只排序一次并复用匹配结果；内联样式仍逐元素覆盖。普通 p/div 使用单换行，特殊段落保留边界；旧版缓存紧凑化同步重映射图片、源样式、阅读位置和标注的 UTF-16 范围，保持书籍和标注 ID。旧私有正文文件只在书架新元数据成功保存后且确认无引用时清理，原文件保留。

小说和漫画分别保存背景、亮度、阅读模式、音量键及其它阅读偏好；旧版漫画先继承既有设置，再分别保存。夜间开关按用户要求全局同步。字体导入记录发起时的模式，结果回调不会改到另一模式。新增本地配置往返、旧版迁移和 ViewModel 切换/重启回归。

按用户截图移除主页顶部品牌/搜索栏和阅读首页日期、标语；书架保留书名/作者搜索，外部书签与笔记入口移到小说/漫画切换栏右侧。自定义书架分组各模式独立保存，schema 升至 7，书籍记录 groupId。分组支持新建/改名/删除及书籍菜单移动，组别筛选和阅读状态筛选叠加；同模式不允许重名，两种模式可使用相同名称。删除分组仅清除分类，书籍回到未分组，正文文件、阅读进度和标注保留。旧 JSON 缺失组别时默认为未分组。

进度条跳转显示返回按钮，记录之前章节、百分比与文字/图片位置，箭头指向原位置。字体改变后仍返回原字符/图片，关闭工具栏时清空记录，重新打开不恢复。两项 Android 回归覆盖文字跨章跳转、字体改变后返回、漫画向前/后返回及关闭/重开工具栏。

旧 MOBI 将任意向后的锚点/filepos 链接当目录，脚注链接同样符合条件，因而把注释标号或说明识别成标题。现在通过一次语义范围索引排除 noteref/footnote/endnote、相关 role/class 和注释目标，剩余链接限定为首个正文目标前的目录链接组；标题与 pagebreak 的回退也排除注释区域。HTML 注释按原 UTF-16 长度屏蔽后定位，不改变原 filepos 字节索引；可见文字/样式不解析隐藏注释。EPUB 优先真正 toc 导航，排除注释导航、注释引用及注释目标，章节定位忽略注释中的伪锚点。

1.5.1 针对截图中的 96% 停滞：此位置已完成记录解压与图片枚举，接下来是目录扫描。旧 anchor/header/style 正则在大量缺少闭合标签时反复扫描到 EOF；本机 JDK17 单独复现 400/800/1600 个未闭合 name anchors，8.8/17.6/35.2KB 分别为 79/241/914ms。现在用单向、识别引号的标签扫描，不再从每个开头重试整段；关闭的 style/script 内容作为原始文本跳过，CSS 字符串内的假 body/h1 不进入目录。样式关闭标签按名称索引、祖先选择器用整数身份与有限缓存，未闭合连续标题隐式结束在下一标题；长无花括号 CSS 按字符位置前进。正文只分配声明长度的单一 buffer，减少全书复制，继续验证展开总长度、尾部截断与 64MB 上限。

新增回归包含 10MB 正文、5 万个未闭合锚点、畸形 tags/head/style、深栈与不存在的 closing、选择器缓存上限后的独立声明、标题边界、96% 后的目录进度与取消。读取任务的 job 取消检查传到目录、样式及 HTML 转换，目录整理继续更新最后一段进度。图片事件也复用单向标签扫描，识别属性中的 quoted > 并保留 UTF-16 偏移。上述合成数据和桌面基准不代替用户具体 MOBI 在手机上的验证。

导入模式在发起时捕获，用户切换模式不改变该任务的 PDF 解释方式。受控 held DocumentsProvider 测试在真实 ViewModel 和界面中检查：进度卡显示、导入期间顶部“＋”禁用但其它导航可用、模式切换后恢复卡片、成功落盘后只显示实际书籍，以及坏 MOBI 失败清卡并保留旧书。自定义目录重建迁移现有书籍/标注时仍显示独立“正在更新目录”窗口，避免用户并发删除、移动或新增笔记被旧快照覆盖；此窗口不用于文件导入。

已启用云上传的书籍菜单增加“删除云端文件”确认。先暂停本书自动备份并等待手动上传取消，再持 cloudOperationMutex 删除仅 `books/<safeId>/` 的整个目录，包含旧 revision 与残缺块；预检索引版本，条件写遇到 412 重读并保留其他书。404 视为已经删除，207 部分失败不报告成功，目录删除后索引失败允许重试。成功清理该书 pending、云封面缓存和历史资格；本地正文、阅读位置和笔记保留，只有未下载的云端占位书与关联记录移出书架。删除与取消都协调自动 worker 的 guard 与同一把锁，旧 history 不会在重启后重新开启资格。协议依据 [WebDAV DELETE for Collections](https://www.rfc-editor.org/rfc/rfc4918#section-9.6.1)。

新上传块为 1 MiB（1,048,576 字节），32 GiB 最多 32768 块，原元数据与资产数量限制不变。checkpoint v2 保存 partBytes；旧 v1 按原 4 MiB 读取并继续同 revision，避免已确认块被新 1 MiB 边界误解释。旧 128 MiB 已提交清单仍能读取。4 项新增界面回归覆盖网格/列表真实触摸取消不打开正文、首页/历史入口、删除菜单条件及确认/取消、繁忙禁用；仅已编译。没有连接真实坚果云账号执行删除，也未在手机上验证按钮触摸或取消时的系统通知。
